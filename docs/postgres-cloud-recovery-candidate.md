# Fixed-export cloud recovery acceptance

This is an inactive implementation candidate, not evidence of a production backup or recovery. The source remains the fixed FCUNO endpoint and Google never receives its native password, signing private key, administrator key, or arbitrary SQL access. The dedicated source reader still has PostgreSQL PUBLIC-function residual rights: the approved security boundary is the fixed export service, not an intrinsically non-writable native role.

## First-copy and activation sequence

1. Deploy the reviewed source/runtime and Google receiver with recurring activation off. Verify the non-export native/TLS/role smoke separately.
2. Within the approved source window, invoke `--execute-approved-first-copy` only with `POSTGRES_BACKUP_FIRST_COPY_APPROVED=1` and `POSTGRES_BACKUP_RECURRING_ENABLED` unset. Existing source admission, authentic budget, signed completion, exact-generation GCS readback and fencing remain mandatory. Do not overlap an active export or force work for a green status.
3. Use the resulting immutable manifest descriptor, source verification **public** key, existing authenticated budget configuration and reviewed 40-character source commit with `createRecoveryBuild` in `lib/postgresRecoveryBuild.mjs`. The returned Cloud Build spec pins the existing backup service account and public images; it disables logs, uses ephemeral disk, and has a bounded lifetime. Supply only a reviewed source archive to Cloud Build. Do not assume IAM or free quota; verify both before dispatch. No new permanent service, database capacity upgrade or grant is created by this code.
4. The network-capable download step verifies the whole signed archive while streaming exact GCS generations into private ephemeral disk. A separate non-root container restores it with **no network, no credentials, no Linux capabilities, a read-only root filesystem, and only three explicit mounts**. It uses the independently proven pinned Supabase PostgreSQL17.6 image/ICU153.121 closure. Neither the image's normal Supabase entrypoint/configuration nor hosted service credentials run.
5. Every ordinary table's complete COPY-row multiset is compared against the archive using duplicate-preserving SHA-256 leaves and bounded external sort. Twelve current catalog sections, exact extension versions/owners, full TOC accounting, global role attributes/membership grantors, original database owner/locale/ACL/comment and every sequence state must match. Source role copies are NOLOGIN and password hashes are never included. The result is not based on selected example rows.
6. A network-capable publisher independently checks the actual container exit/containment, exact proof/archive identity, source signatures and private build plan. Only then may it create `runs/<runId>/recovery.json`, verify its immutable generation/CRC/SHA readback and produce the small non-business acceptance descriptor. This descriptor must be independently reviewed and pinned as `POSTGRES_BACKUP_RECOVERY_ACCEPTANCE_JSON` before weekly activation. Merely copying an archive cannot unlock it.
7. Normal `--execute-recurring-weekly` refuses to contact the source without the pinned, verified recovery acceptance. It rejects altered/foreign/future/stale acceptance and preserves all existing copies on failure. The first acceptance expires after90days; recurring re-verification and source-key renewal need operational scheduling before expiry. This code does not silently promise permanent access.

## Scope and explicit fail-closed limits

The proof establishes an independent **logical PostgreSQL** recovery, not a replacement of Supabase's entire hosted platform. Hosted-service configuration, login passwords, external Storage file bytes and the Vault root encryption key are outside `pg_dump`; daily file backups remain separate. Current source catalog checks showed no large objects, materialized views, non-config extension tables or Vault secret rows. This verifier refuses to certify a future archive with any such unsupported contents rather than silently omit them. An opaque Vault ciphertext round-trip alone is not decryptability proof.

The existing1GiB Cloud Run job cannot safely host the2.9GB restored database. Cloud Build's disk-backed disposable workspace avoids that limitation without using this Mac. The restoration container is capped at2GiB; it does not change FCUNO database capacity. Runtime/build duration and actual billed cost must be measured on the real first proof. Four-week retention remains a separate reviewed policy; this candidate does not delete recovery copies or invent a lifecycle rule that could erase still-referenced generations.

## Local verification

`tests/postgres-backup-native.test.mjs` executes a real synthetic TLS native export, signed stream decode and the **same offline recovery controller** used in Cloud Build. It verifies all synthetic rows, metadata, memberships/grantors and sequence states; it is not a mocked restore. `tests/postgres-recovery.test.mjs` adds adversarial activation, hash/generation, containment, credential, timing and SQL-identifier tests. Linux image/controller proof and the first real cloud archive remain separate gates; passing local tests must not be presented as those completed gates.
